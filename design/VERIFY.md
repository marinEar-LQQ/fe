# 실제 음성 검증 안내서 (온라인 모드)

대상: 프론트·백엔드 저장소를 받은 팀원. 실제 클라우드 모델(Gemini 전사, NVIDIA 번역)로 시연 녹음 3개를 분석하고, 정답(`team/truth.json`)과 비교해 결과를 기록한다.
화면 흐름은 Mock 엔진으로 이미 확인했다(아래 "이미 확인된 것"). 이 문서는 **실제 모델 결과**와 **실제 중계 서버 연결**을 확인하기 위한 것이다.

## 0. 준비물

- 두 저장소를 나란히 받는다: `marinear-frontend/backend`, `marinear-frontend/frontend`
- Node.js 20 이상, Chrome
- API 키 2개: `GEMINI_API_KEY`(음성인식), `NVIDIA_API_KEY`(번역) — 팀 리더에게 받는다

> ⚠️ **키는 절대 커밋하지 않는다.** `backend/.env` 는 `.gitignore` 에 들어 있다. 커밋 전에 `git status` 로 `.env` 가 목록에 없는지 확인한다. 화면 캡처·메신저에 키를 붙여 넣지 않는다.

## 1. 중계 서버 실행 (백엔드)

```bash
cd backend
git pull
npm install
# backend/.env 파일을 만들고 두 줄을 넣는다 (따옴표 없이)
#   GEMINI_API_KEY=...
#   NVIDIA_API_KEY=...
npm run server          # http://localhost:8787 — 이 창은 켜 둔다
```

확인: 브라우저에서 <http://localhost:8787/api/health> 를 열면 `{"asr":true,"translate":true,...}` 가 보여야 한다. `false` 면 해당 키가 `.env` 에 없다.

## 2. 프론트 실행

```bash
cd frontend
git pull
npm ci
npm run dev             # http://localhost:5173 (온라인 모드가 기본)
```

- 중계 서버 주소가 다르면 `VITE_PROXY_URL=http://주소:포트 npm run dev`
- 처음 열면 **언어 선택** → 시작

## 3. 시연 작업 등록

오늘 작업에서 다음과 같이 등록한다 (시연 대본 기준, **일부러 틀린 기록** — HPNT 로 바뀌는 교신을 잡아내는지 보기 위함):

| 항목 | 값 |
| --- | --- |
| 내 선박명 | 해동호 |
| 작업 대상 선박 | 현대부산호 |
| 터미널 | PNIT |
| 선석 | T2 |

설정 › 분석 엔진에서 **온라인 · 중계 서버 · 전사 사용 가능 · 번역 사용 가능**을 확인한다.

## 4. 파일 분석

교신 › **파일 분석** → 아래 파일을 하나씩 고른다 (한 파일 분석이 끝난 뒤 다음 파일):

- `frontend/node_modules/marinear-engine/fixtures/audio/team/script1_noisy.wav`
- `…/team/script2_noisy.wav`
- `…/team/script3_noisy.wav`

첫 분석 전에 **"음성이 외부 서비스로 전송됩니다"** 동의 창이 떠야 한다 → 동의.
발화마다 카드가 `분석 대기 → … → r1(잠정 판정) → r2` 로 바뀐다. 발화당 몇 초 걸린다.

## 5. 결과 비교표

## 6. 전체 흐름 체크리스트 (온라인)

- [ ] 첫 실행 언어 선택 → 오늘 작업 등록 → 교신 화면
- [ ] 상단에 **온라인** 표시, 설정에 중계 서버·전사·번역 **사용 가능**
- [ ] 첫 분석 전 개인정보 동의 창 → 동의 후에는 다시 묻지 않음
- [ ] 1-1 장소 차이 카드 → "등록 장소와 비교 보기" → 기록 PNIT / 교신 HPNT 강조
- [ ] 확인 체크 → **확인 후 앱 기록에 반영** → 상단 작업 기준이 v2 (HPNT T2)
- [ ] 1-2 재확인 필요 카드 → 핵심 구간 재확인 → 원음/완화음 결과, 원음 구간·완화음 구간 재생, `[PNIT / HPNT]` 강조 → 확인 표시만 하기 (기준 그대로)
- [ ] 설정 › 언어 en / id / vi → 카드에 번역(정형 요약 카드 + 번역문). 한국어 원문은 그대로. 불확실 값은 `[A / B]` 와 "확인 필요"
- [ ] 작업 일지: 통계 3칸, 기준 변경(v1→v2)·사용자 확인·교신이 시간순, 음성 듣기 재생
- [ ] 작업 후 메모 입력 → 일지 저장 → TXT·JSON 받기 → TXT 안에 `불확실: terminalId=[PNIT / HPNT]`·메모·기준 변경이 있음
- [ ] 새로고침 → 작업 기준(v2)과 교신 목록이 그대로
- [ ] (선택) 수신 시작 → 무전기 변환 장치/마이크 입력 레벨, 말소리가 카드로 들어옴 → 수신 중지
- [ ] 중계 서버 창을 끈 뒤 파일 분석 → **온라인 분석 서버에 연결할 수 없습니다** 안내·다시 시도·오프라인 모드로 전환 링크 (원음 보존 문구) → 서버 다시 켜고 "다시 시도" → 연결 확인됨
- [ ] 태블릿·휴대폰에서 볼 때: 지금 중계 서버는 `127.0.0.1` 에서만 열린다 → 같은 PC 의 브라우저로만 검증 가능 (README "배포 시 주의")

## 7. 문제 기록 양식

문제마다 하나씩 복사해 이 파일 아래나 이슈에 붙인다. **API 키·개인 정보는 적지 않는다.**

```text
### [번호] 한 줄 제목
- 날짜·시각:
- 기기/브라우저: (예: Windows 11 노트북 / Chrome 131)
- 엔진 모드: 온라인 / 오프라인 / 시연
- 화면: (교신 / 재확인 / 작업 일지 / 오늘 작업 / 설정)
- 입력: (script1_noisy.wav 의 1-2 발화 등)
- 기대한 것:
- 실제로 본 것:
- 화면 알림의 오류 코드(있으면, 예: ONLINE_UNAVAILABLE)와 작은 글씨 메시지:
- 재현 방법 (1, 2, 3 …):
- 캡처 파일 이름:
- 중계 서버 창의 마지막 로그 몇 줄 (키가 보이면 지우고):
```
